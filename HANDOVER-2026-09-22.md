### 4.2 What it changes

- **Vertical rhythm tokens** appended to tokens.css: `--section-pad`
  (2rem phone / 3rem desktop), `--page-top` (2.5 / 4rem), `--hero-gap` (1rem).
  Sections are padded by HALF the wanted gap so two meeting sections make one
  gap. Targets: between sections 64/96px, header→title 40/64, title-or-photo
  →content 48/64, last content→footer 64/96.
- `.section` uses `--section-pad`; `PageHero`, `PageHeroImage`, the CMS page
  title block and Casting title use `--page-top`/`--hero-gap`; the footer's
  top margin is `--section-pad`; page-level overrides that doubled spacing
  were removed or zeroed (listed in each file's comments).
- **Left-aligned reading columns** — root cause: `.container` has
  `margin-inline: auto`, and several pages narrowed a `.container` with
  `max-width: 68ch`, which CENTRED the text column while titles, photos and
  buttons stayed on the left edge. Fixed by limiting the children instead:
  `.x > :global(*) { max-width: 68ch }`. Pages: CMS pages
  (Young Performers, Scholarships, blog), Casting, School Play in a Box,
  Stories on Stage (auditions + explainer), Thank you. Also left-aligned:
  Casting's CTA, Photos "Find your photos" card, Newsletter signup form card.
- Global default `.section-head { margin-bottom: var(--space-md) }` (pages
  that set their own keep it; SPIB, Audition, Photos, About, Judy Robe had none).
- Pages that END in a tinted band run straight into the footer:
  `main:has(> :last-child:is(.board-section, .auditions-promo-section,
  .inquiry-section, .sponsor-section)) ~ .site-footer { margin-top: 0 }` —
  `~` not `+` because a script sits between `</main>` and the footer.
  `:has()` needs Safari 15.4+ / Firefox 121+; older browsers just show a
  48px white strip (harmless).
- **Deliberately still centred:** home Donate button (PM asked in Aug 2026
  for it centred under the thermometer), home Values band, Shop's lone
  "Coming soon" message, Volunteer empty-state note.

## 6. WORKING RULES AND PREFERENCES — FOLLOW WITHOUT BEING ASKED

### 6.1 The PM's standing rules (restated at the start of every session)

1. **Mockups:** for anything visual, generate an actual PNG first and show
   it. **Do NOT use the interactive widget/visualizer tool — it doesn't
   render for the PM.** Always attach with `present_files` — once this
   session files were created but never attached and the PM couldn't see them.
2. **Label files:** when a reply contains both mockups and repo files, say
   explicitly which is which ("MOCKUP ONLY — do not upload" / "REPO FILE").
3. **Code handoff:** never paste raw code into chat. A file to download plus
   a GitHub link.
4. **Links:** a specific GitHub link for EVERY file in a batch — edit,
   create-new, upload or delete as appropriate. Never "same links as last
   time". The PM has had to ask for missing links repeatedly (again this
   session: "provide links for each of the 13 files").
5. **New files first:** if a batch includes a brand-new file others depend
   on, say so and number the steps. Always say whether it is safe to stop
   halfway — the PM works in short bursts.
6. **New or awkward filenames:** new files, square brackets, no extension or
   unusual extensions → GitHub "Create new file" and paste (downloading and
   re-uploading mangled names and broke four deploys once).
   - **Extensionless files (`_headers`) open BLANK in the PM's file viewer**
     — hand over a `.txt` copy, tell them to paste into the real name, and
     check the breadcrumb before committing (`_headers.txt` is silently
     ignored by Cloudflare).
   - **Binary files (images) cannot be pasted** — use GitHub "Upload files",
     then check the exact filename in the file list (a browser may add " (1)").
   - For EXISTING files with square brackets, the edit link + paste is fine;
     name the download something bracket-free and say which file it replaces.
7. **CMS cache:** whenever `public/admin/config.yml` changes, remind them to
   hard-refresh the CMS (Cmd+Shift+R) or use incognito. This really matters:
   this session the old cached "required photo" rule kept blocking a save.
8. **Pasting:** for every pasted file give the expected line count and the
   first line, and say "click into the editor, Cmd+A, then paste". A partial
   paste once took the site down.

### 6.2 Preferences learned (2026-08 and this session)

- Approves mockups fast, in one line. Give **a clear recommendation plus one
  alternative** — not a menu of options with no steer.
- Will overrule a recommendation; build their choice without re-litigating.
- Reports problems with screenshots — read them closely; the real cause is
  often deeper than the symptom shown.
- Notices inconsistency between page types; many jobs start as "this page
  doesn't match that one".
- Asks "how do I…?" when the fix may be theirs. **Always say whether it's a
  CMS edit they make or a code file you supply**, and prefer the CMS route
  when it can do the job (e.g. removing hero photos, cast page URLs).
- Wants numbers, not impressions ("187px against 96px elsewhere"). State
  what was measured and what could not be verified.
- Busy; types quickly with typos. Write plainly, no jargon; don't grovel
  when corrected; say plainly when something works.
- Uses a Mac (Cmd shortcuts, Terminal is available and they can run a
  pasted `curl` command if told exactly where Terminal is — it's an app on
  their Mac, not in Cloudflare).
- Works in short bursts; values "safe to stop here" guidance.
- Cares about child-safety/privacy but is pragmatic — when the organisation
  decides (e.g. public cast list), record the decision and implement it.
- Prefers things that look deliberate and sophisticated rather than
  "childish"; asked for the duotone scheme, full-width carousel, even spacing.

## 7. HOW THE SITE IS BUILT NOW

Astro static site + Decap CMS, hosted on Cloudflare Pages. Every CMS save is
a commit; Cloudflare rebuilds in ~1 minute. **There is no staging** — every
commit to `main` goes live on the preview address.

**Fonts:** Archivo Black (headings, `--font-heading`), Baloo 2 (home Values
band only now), Source Sans 3 (body). Loaded from Google Fonts.

**Colour — the duotone scheme (live since 2026-09-21).** Explained at the top
of `tokens.css`.
- Teal family: `--surface-brand` #b5dce3 (header, footer), `--paper-warm`
  #e9f4f7 (panels/bands), `--campaign-fill` #338899 (graphics only),
  `--ink` #0e323a (all text — deep teal, not black), `--surface-deep` #0e323a
  (numbers band, header chips). Legacy names `--nav-bg-dark`/`--nav-text` are
  kept as aliases — documented in tokens.css.
- PYT pink `--accent` #c0287b / `--accent-deep` #97215f — **"pink means
  press"**: reserved for clickable things (buttons, promo banner, links,
  their hover/focus tints). `--highlight` (Donate) is pink.
- Contrast rules: pink TEXT on pale teal must use `--accent-deep` (plain pink
  is 3.74:1 there — fails); `--campaign-fill` never for text.
- Exceptions on purpose: the multicolour logo; the home Values phrases keep
  pink #a82169 / blue #2f7fa3 / green #4a8038 (PM request) — only on the teal
  WASH; on `--surface-brand` the blue drops to 3.05:1 and merges.
- Header: Tickets/Calendar/Register are deep-teal chips; **Donate is the only
  pink header button**. Stat tiles pale teal on the deep band. Category tags
  on Shows/Audition are three strengths of teal.
- Known leftover non-clickable pink text (offered as a follow-up, not done):
  About job titles, Judy Robe year heads/names, Programs "Scholarships
  available" tag, Shop "Coming soon" eyebrow, Stories production dates,
  "Interested in auditioning?" strips.

**Duotone photos.** On pages with 2+ grid/carousel photos, photos get the SVG
filter `#pyt-duotone` (defined in `BaseLayout.astro`: greyscale, gamma 1.45,
dark #0b2a31 → light #d3edf1) and bloom to full colour when featured
(carousel `.is-featured`) or hovered/focused. Always full colour: pages with
ONE photo (a script in BaseLayout counts and sets `data-duotone` on `<html>`,
so trimming a list to one item flips that page back automatically), page
hero photos, photos inside written content, the logo. Posters/board photos
only count when they have an inline `background-image` (placeholders with
initials/titles are not photos). **The photo selector list exists in BOTH
BaseLayout.astro and global.css ("DUOTONE PHOTOS") — change both together.**
With JavaScript off, everything shows in colour.

**Home carousel** (`index.astro`). One photo fills the strip (`flex: 0 0 100%`),
3:2 desktop / 4:3 phones, arrows inset at z-index 3 (they were hidden under
the photo before — the left arrow was invisible on phones on the old live
site), edge fades removed, neighbour dimming off (`FADE_OPACITY = "1"`),
looping unchanged. It opens on the card titled "center stage musicals" —
**the PM has since renamed the titles to long sentences** ("Center Stage
Shows - professional scale musicals where everyone is cast." etc.), so that
match now fails and it falls back to the first card, which is still Center
Stage. Harmless; worth updating the match and checking how the long captions
wrap on phones. Carousel photos need ≥2000px wide originals (the old low-res
screenshots were replaced by the PM on 2026-09-21).

**Logo** (`Logo.astro`). Nav size (header on inner pages + footer on EVERY
page) uses `/uploads/pyt-logo-transparent.png` — the PM's transparent file,
cleaned of a 4–10px white rim and resized to 600px; heights 42px/51px chosen
so the letters match the old 44/54px. Hero size (homepage, on white) still
uses `/uploads/pyt-logo-stars.png` (its crop offsets were measured from that
file). **Both live in `public/uploads` = the CMS media library — nobody
should delete them.**

**Home hero headline** — CMS "As typed / UPPERCASE" switch; line-height 1.05
as typed vs 0.88 uppercase (lowercase descenders collide at 0.88 — measured).
The size is Option B (clamp 2rem / 6.2vw / 3.4rem; do NOT raise to 3.6rem —
2px headroom). CMS hint: ~35 characters fit one line as typed, ~28 in caps.

**Promo banner** (`PromoBanner.astro`, CMS Home Page → Promo Banner): full
width, pink with white text (5.48:1), shown only when ticked AND text AND link
are filled; external links open in a new tab. Still forces capitals

**Cast pages** (`src/pages/cast/[slug].astro`): soft client-side password gate
(NOT security). Order: intro → Rehearsal resources → Cast list → Rehearsal
schedule. Both sheets embed in wide frames (up to 1600px). Cast list:
published link → embedded like the schedule, no button; private link →
embedded + "Open in Google" button; blank → hidden. URL of a cast page is
`/cast/<slug>`, slug fixed at first save (renaming the show title doesn't
change it). The embed helper accepts a normal sharing link (`#gid=` picks the
tab) or a published `/pubhtml` link.

**CMS-made pages** (Pages collection → `src/pages/[...slug].astro`): title,
optional hero photo, rich-text body with links and images, optional closing
quote and CTA button, "Add to navigation" off by default. The Blog page and
posts (e.g. `/blog`, `/pyt-launches-new-website`) are made this way — one
page per post, no automatic index (the PM links posts from /blog by hand).

**Page Hero Images** (CMS list, `page-heroes.json`): one row per page, photo
now optional (removing the photo or the row = no hero). Stories on Stage and
Studio Shows rows were removed on purpose. Musicals has no row.

## 10. TRAPS THAT HAVE CAUSED DAMAGE OR NEARLY DID

### 10.1 Webfonts in the sandbox (cost a shipped nav bug)
Google Fonts is unreachable from the sandbox; measuring without Archivo Black
gives answers ~90px too small. `document.fonts.check()` returns true for a
fallback — **verify `[...document.fonts]` shows the family "loaded"**.
Method: download from `https://raw.githubusercontent.com/google/fonts/main/ofl/`
(`archivoblack/ArchivoBlack-Regular.ttf`, `baloo2/Baloo2[wght].ttf`,
`sourcesans3/SourceSans3[wght].ttf`), copy into `dist/testfonts/` AFTER each
build (the build wipes dist), serve dist with `python3 -m http.server`
(start it with `nohup setsid … &` — it dies otherwise), inject `@font-face`
and `await document.fonts.load(...)`.

### 10.2 Pasting (took the site down once)
Always "click in, Cmd+A, paste" plus expected line count and first line.
Diagnostic: clone main and compare each handed-over file byte-for-byte.

### 10.3 Over-broad edits
A regex cleanup once removed a live prop. Prefer exact, asserted
replacements (assert the old text occurs exactly once). **Blank-line
differences** broke exact matching this session — match tolerant of blank
lines, or view the exact text first. When a pattern occurs twice (e.g. a rule
repeated inside a media query), patch the first occurrence deliberately.

### 10.4 Batch size
Every hand-paste is a risk. A 35-file invisible cleanup was cut to 5 files in
August. Offer to split large batches (the §4 batch splits cleanly into A/B).

### 10.5 Astro scoped styles win
Scoped rules (`.x[data-astro-cid]`) out-rank global and injected CSS. Test
overrides need `!important` or doubled classes, or they silently lose.

### 10.6 The header is tight at 1120px
Measure header height/wrap before and after anything that touches the
header (77–80px, one row; the logo swap was sized to change width <2px).

### 10.7 `.container` centres itself
Never narrow a `.container` to make a reading column — limit its children.

### 10.8 The sandbox's network is limited
docs.google.com, pages.dev, Behance, archive.org and most image hosts are
unreachable; `web_fetch` can read some pages as text but not images. Ask the
PM to run live checks (`curl` in Terminal, iPhone tests) and say so honestly.

### 10.9 Screenshot quirks
Full-page capture resizes the viewport, which un-centres the carousel — set
the viewport to the page height, wait ~1s, then screenshot the viewport. A
`clip` taller than the viewport is cut off.

### 10.10 Content-only scans miss code references
Unused-upload scans must also search `src/components`, layouts and pages
(the logos are referenced from code).

### 10.11 Temporary content edits for testing
When testing (e.g. blanking a CMS field), always back up, restore and
`git status` to confirm content files are unchanged before packaging.
