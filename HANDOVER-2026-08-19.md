### ⚠️ New lesson this session — verify before handing off
Partway through this session, a fix was built, tested, and verified working
in the sandbox — but the files actually **sent** to the PM turned out to be
a stale pre-fix version (a handoff copy/paste error, not a PM upload
mistake). The PM uploaded the wrong content twice, correctly, because that's
what they were given. Diagnosed by re-checking what was actually live on
GitHub against what was sent.

**Going forward: before calling `present_files`, `diff` every file you're
about to hand over against the tested sandbox source, and only send once
they match exactly.** This cost real time and trust — don't skip it again.

## 3. THE BUILD-AND-HANDOFF LOOP (unchanged, still follow exactly)

1. **Re-sync to live first**: `git fetch origin main -q && git reset --hard origin/main -q`.
   Treat live `origin/main` as source of truth for content. Never overwrite
   live content fields without explicit say-so — when editing a JSON content
   file, touch only the specific field(s) needed.
2. **Build in the sandbox**, `npm run build`, confirm page count (currently
   31 — note: the build tool's own summary line sometimes prints "30
   page(s)" while the actual file count is 31; count `find dist -name
   index.html | wc -l` if the two ever seem to disagree, don't panic at the
   summary line alone).
3. **Verify rendered HTML by PARSING, not raw grep** (§6F false alarms are
   real and happened multiple times this session — e.g. a CSS class name or
   an HTML comment matching a grep pattern with no actual element present).
   Use Python regex for real elements.
4. **Empty-safe everything.** Test by blanking a field, rebuilding, checking
   the real element is gone, then restoring.
5. **Verify the handoff files themselves** — see the lesson above. `diff`
   outputs against sandbox source before sending.
6. **Update `BUILD_LOG.md`** — newest entry at the top.
7. **Hand over with `present_files` + explicit GitHub links + on-screen
   checks.** New files use the `/upload/main/<folder>` page (has a "choose
   your files" button) for images/binary files — the `/new/main/<folder>?filename=`
   text-paste page is for text files only and has caused at least one mixed-up
   upload this session when the PM had multiple such tabs open. Drag-and-drop
   to GitHub has been unreliable for this PM more than once; the button-based
   upload page is the reliable fallback.

### Deploy troubleshooting (reconfirmed this session)
- Multiple commits close together → all but the newest often show "No
  deployment available." **Normal, not a failure.** Only the newest commit's
  status matters.
- A genuine red ✗ build: get the ACTUAL Cloudflare build log text from the
  PM (Details → the log), don't guess from memory. This session's one real
  red build was traced to a create-new-file upload where the wrong file's
  content got pasted in — the error message named the exact broken JSON
  file directly.

## 5. WHAT WAS DONE THIS SESSION (all live and verified unless noted)

This was a **very long session** covering a full visual redesign pass. In

1. **Homepage photo strip** (hero) — 6-card scrollable strip linking to key

2. **Site-wide "bolder" redesign**, inspired by a couple of reference sites
   (Seattle Children's Theatre, Encore Stage & Studio) the PM shared:
   - Dark nav bar (`#17151a`), plain-text nav items (no more lilac pills),
     bright yellow Donate button (`--highlight: #f2c419`), later a pink
     Register button added alongside it (uses the standard `--accent` pink,
     no special override).
   - Headline font for headings site-wide: **Archivo Black** (via the
     shared `--font-heading` token — genuinely site-wide, every page).
   - Corners: buttons/pills/nav controls get a small `--radius-btn: 4px`
     softening; **cards and photos are fully square (`--radius: 0`)
     site-wide** (rolled out from homepage-only to everywhere).
   - Real PYT logo (colorful star "PYT" mark + "Peninsula Youth Theatre"
     wordmark, one image file: `/uploads/pyt-logo-stars.png`) replacing the
     old placeholder "P" mark everywhere — nav (small), homepage hero
     (large, see below), and footer. The old file `/uploads/pyt-logo.png`
     is now fully unused, harmless leftover.
3. **Homepage hero rebuild** — this took many iterations, landed on:
   - Logo removed from the nav bar **on the homepage only** (every other
     page keeps the small nav logo); large version sits beside the headline
     on desktop (≥720px), stacked above it on phones.
   - Logo's "hero" size uses a **precise crop-alignment**, not just a scaled
     whole image: the frame is sized to the headline text block's real
     height, and the image is scaled bigger and shifted up inside it so the
     "PYT" letters' top (not the decorative stars above them) lines up with
     the headline's top, and the wordmark's bottom lines up with the
     headline's bottom. The crop percentages (26.47% / 97.50% of the image's
     total height) were **measured directly from the actual image file's
     pixel rows** — see `src/components/Logo.astro` comments. **If the logo
     artwork is ever replaced, these need remeasuring.**
   - Headline font switched from Archivo Black to **Baloo 2, bold, caps** —
     but **only for this one homepage headline**, via inline `font-family`
     in `index.astro`, not the shared token. Needed an explicit tight
     `line-height: 0.82` because Baloo 2's own font metrics reserve a lot of
     unused vertical space (measured directly, not guessed).
   - Headline forces a two-line break: whichever word comes right before the
     CMS-editable "accent word" joins it on line 2 (currently renders
     "YOUTH THEATER" / "FOR EVERYONE!"). Falls back to natural wrapping if
     no accent word is set.
   - The accent word gets a **hand-drawn star trail** (not a line) — starts
     under the word, sweeps up into the empty space under the line above.
     **Hand-tuned to the CURRENT exact headline wording and Baloo 2's
     metrics — will need retuning if the headline text changes
     substantially or the font changes again.**
   - Hero intro paragraph (lede): bigger, bolder, full-ink color (was muted
     gray), tightened line-height/letter-spacing.
   - Shows/Programs buttons removed from under the hero text entirely (the
     CMS fields behind them still exist, unused, not deleted).
   - Footer now uses the same shared `Logo` component (nav size) instead of
     its own separate old logo + a duplicate "Peninsula Youth Theatre" text

## 6. CONFIRMED PM PREFERENCES & DECISIONS (carry these forward)

- **Design direction**: bolder, higher-contrast, more playful than the
  original soft-pastel placeholder look — explicitly inspired by Seattle
  Children's Theatre and Encore Stage & Studio as references. Still
  explicitly **placeholder colors/fonts/logo-scale pending final branding**
  — the PM has said this multiple times; don't be surprised by another
  round of visual changes later.
- **Corners**: square everywhere except buttons/pills/nav controls, which
  get a slight 2-4px softening. This is now the standing site-wide rule.
- **Headline font**: Archivo Black is the site-wide default for all
  headings (via the shared token). Baloo 2 is a **deliberate one-off**
  for the homepage hero headline only — don't assume it should spread
  elsewhere without being asked.
- **Homepage hero logo**: must align precisely to the headline text (top of
  "PYT" letters to top of headline, bottom of wordmark to bottom of
  headline) — this took several rounds to get right and the PM cared a lot
  about precision here, not just "looks about right."
- **Star-trail flourish over CSS underline** for the headline's accent word
  — chosen explicitly over a plain wavy-line underline after seeing both.
- **"Ways to join" cards**: title overlaid directly on the photo (not below
  it, unlike the hero photo strip which uses below-photo captions) — two
  different card conventions exist on the homepage now, both intentional,
  don't try to "unify" them without asking.
- **Heading capitalization**: PM wants a per-heading choice, not a single
  site-wide rule — this is now a real content-model feature (see §4), not
  just a one-off fix.
- **Scope discipline**: when asked to make "the whole homepage" editable in
  some way, the PM explicitly limited it to the **homepage only**, not the
  rest of the site, when asked to clarify. Don't assume a homepage pattern
  should silently spread site-wide — ask.
- **Audition/tickets is the bar for "upcoming"** on the homepage strip now,
  not just "hasn't happened yet." This was a deliberate content-strategy
  decision, confirmed explicitly, not a guess.
